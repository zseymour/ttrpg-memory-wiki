# Rules and sources compose through a versioned Source store

Campaign memory never contains rules text or source documents. All citable outside-of-play material — System corpus content and Authored sources — lives in a versioned, read-only Source store under one bibliographic identity, version, and locator scheme, with store-assigned Rule identities whose cross-version continuity exists only where declared, never inferred. Campaign memory holds only Corpus pins, version-frozen citations with bounded Claim evidence, Campaign rulings, and ingested items; Rule context composes pinned corpus material at recall without copying. Rejected alternatives: importing rules into the authoritative record (drags every errata through the operation log and grants sources standing), live adapter lookup services (unreproducible citations, no export replay), and locator-only or content-hash citation (rulings dangle across editions).

## Consequences

Pin what composes live; freeze what was ingested. A Corpus pin change owes Pin reconciliation — cited items intersecting declared revisions are reconfirmed, revised, or retired, or remain visibly unreviewed, a standing distinct from and milder than a Ruling conflict — while later versions of ingested sources create no obligation and are adopted only through a new Source import whose entries supersede or coexist item-by-item. Content-kind declarations, including Declared transitions, are versioned and campaign-pinned symmetrically to the corpus. Store versions are immutable once minted; normalization tooling is uncontracted, and re-processing mints a new version. The store is an optional deep layer: Campaign export and replay depend only on citations and Claim evidence carried by memory items, never on store availability.

# Long-campaign acceptance uses deterministic seeded simulation with a predicate oracle

Long-campaign acceptance runs a hand-authored scenario skeleton interleaved into seeded, procedurally generated adversarial mass — confusable near-miss material derived per semantic axis from the skeleton's own vocabulary, constrained to be confusable but never contradictory — rather than an LLM-simulated campaign or a small hand-authored trace. Outcomes are judged by plan-agnostic predicate assertions (must-include with correct Recall qualification, must-exclude across items, references, manifests, and gap wording, plus log, receipt, lifecycle, and export-replay assertions) that are binary at every scale; renderings receive structural checks only, and performance is a report-only work factor except that infeasible requests must be rejected without full assembly cost. We chose reproducibility and an honest oracle over generative realism because the same seed must yield the same campaign and expected results across hundreds of sessions, and compensated for lost realism by making the generated mass adversarial and by requiring every entry in a named failure catalog of plausible shortcut implementations to be killed by at least one probe.

# Editable note blocks are keyed by HTML-comment markers

A projected page tags each editable Notes block with an HTML-comment marker `<!-- claim:<assertion-id> -->` on its own line immediately above the block. Edit intake associates edited content with the originating assertion by this marker, never by byte offset or ordinal position, so a marker survives rewrap, blank-line insertion, and indentation normalization while the content beneath it is renormalized before comparison. HTML comments were chosen because they render invisibly in every target editor (Obsidian preview, VS Code, GitHub, mobile Markdown viewers), are preserved verbatim by the formatters those ecosystems run (Prettier, Obsidian's formatter, `remark`) since none reflow the interior of an HTML comment, and carry no Markdown semantics that could collide with player prose. Rejected alternatives: byte/ordinal association (breaks under any reflow — the failure this project exists to prevent); frontmatter-only ids (cannot tag inline note blocks); visible fenced or heading anchors (leak machinery into the reading surface and collide with player headings); zero-width Unicode sentinels (silently stripped by editors and clipboards, undebuggable when they fail).

## Consequences

Marker→content association is stable across the formatter passes players' editors apply, so a pure formatting edit compiles to zero proposed operations despite byte divergence. A player may delete or duplicate a marker: a missing marker becomes an ambiguous `retract-note` proposal (deletion vs. accident) held for confirmation, and a duplicated marker id is reported as a parse error with the later block ignored rather than silently overwriting. The marker embeds the assertion id, which is stable identity, not editable content; editing the id text does not re-target an operation because intake reads regions from the projection basis, not from the id the player typed. Markers are absent from the authoritative record — they exist only on the Projection surface — so nothing about this encoding constrains the operation log.

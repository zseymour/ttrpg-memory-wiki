# Corpus reconciliation and ruling conflict are structural and derived

Pin reconciliation status and Ruling conflicts are computed from declared, structural inputs, never inferred and never stored as mutable status. A citation is *unreviewed* only when the pinned Source-store version's declared revisions (revised / removed / renamed, composed transitively across the predecessor chain) intersect the frozen citation and no `reconcile-citation` operation has discharged it since the pin — derived at recall from the store's declarations plus the operation log, never a stored flag, and never blocking adoption. Two Campaign rulings conflict only when they cite the same Rule identity (`source` + `ruleId`) over intersecting anchor scope without a declared `precedenceOver` between them — structural overlap on declared citations, never a text-similarity or model judgment of "incompatible." Cross-version rule continuity is the carried-forward identifier itself: an unchanged `ruleId` in a newer version *is* the same rule; `revised` / `removed` / renamed (`continues`) are the declared exceptions.

Rejected alternatives: recording an affected-citation snapshot into the log at pin time (makes *unreviewed* durable but store-independent, at the cost of a mutable obligation store the log must keep in sync — inconsistent with derived standing, and semantically empty once the store that defines the delta is absent); free-text scope matching or model-judged incompatibility for ruling conflict (either brittle exact-string comparison or the confidence / merge-on-alias anti-pattern in normative clothing); requiring an explicit per-rule continuity declaration for every carried-forward id (enormous ceremony and a silent-drift foot-gun).

## Consequences

Reconciliation needs the Source store present to compute, because it reads the store's declared revisions; store-absent export and replay carry the recorded pin operations, frozen citations, and reconcile dispositions, but omit the live *unreviewed* caveat — honest degradation, since deep corpus content is equally unavailable without the store. Ruling conflict and *unreviewed* status cost nothing to store and can never drift from the log. `previewRepin` is a read-only reconciliation query surfacing what a re-pin would affect, not an operation; the review it prompts is submitted as explicit `pin-corpus` and `reconcile-citation` operations under the `pin` act. A house rule that cites nothing never auto-conflicts; conflict-checkable overlap requires a declared citation.
